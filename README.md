# Единая очередь

Веб-система для небольших служб поддержки: принимает обращения из WhatsApp,
собирает их в единую очередь заявок и даёт сотрудникам рабочий веб-интерфейс.

Проект распространяется как исходный код для самостоятельной установки. Это не
готовый облачный сервис: каждая организация настраивает его под себя.

## Возможности

- Единая очередь заявок: статусы, приоритеты, исполнители, передача смены
- Бот в WhatsApp: выбор языка, меню категорий, сбор данных заявки в несколько сообщений
- Переписка с пользователями из веб-интерфейса, вложения, фото, документы
- Роли сотрудников, журнал действий, статистика и отчёты
- Интерфейс на русском, бот на русском и казахском
- Категории, приветствие и вопросы бота задаются в одном файле конфигурации

## Требования

- Python 3.12 (основная часть использует только стандартную библиотеку)
- Node.js 18 или новее (проверено на Node.js 22) для коннектора WhatsApp
- Для постоянной работы: сервер Linux (например, Ubuntu) с systemd и HTTPS-прокси

## Быстрый старт (локально)

1. Установите зависимости коннектора:

   ```bash
   npm ci
   ```

2. Создайте конфигурацию организации:

   ```bash
   cp config/company.example.json config/company.json
   ```

3. Задайте переменные окружения и запустите сервер. `WEBHOOK_TOKEN` — любая
   случайная строка длиной не меньше 32 символов; без неё сервер не запустится.

   Linux / macOS:

   ```bash
   export WEBHOOK_TOKEN="замените-на-случайную-строку-не-короче-32-символов"
   export QUEUE_LOCAL_MODE=1
   export QUEUE_DATA_DIR="$HOME/.local/share/queue-local"
   export QUEUE_WHATSAPP_AUTH_DIR="$QUEUE_DATA_DIR/whatsapp-auth"
   python3 app.py
   ```

   Windows PowerShell:

   ```powershell
   $env:WEBHOOK_TOKEN = "замените-на-случайную-строку-не-короче-32-символов"
   $env:QUEUE_LOCAL_MODE = "1"
   $env:QUEUE_DATA_DIR = Join-Path $env:LOCALAPPDATA "QueueLocal"
   $env:QUEUE_WHATSAPP_AUTH_DIR = Join-Path $env:QUEUE_DATA_DIR "whatsapp-auth"
   python app.py
   ```

4. Откройте http://127.0.0.1:8000/setup и создайте первого администратора.
   Эта страница доступна только в локальном режиме и только пока в системе нет
   пользователей.

5. В другом терминале задайте те же `WEBHOOK_TOKEN`, `QUEUE_DATA_DIR` и
   `QUEUE_WHATSAPP_AUTH_DIR`, затем запустите коннектор:

   ```bash
   npm start
   ```

   Отсканируйте QR-код в WhatsApp на телефоне (Связанные устройства).

`QUEUE_LOCAL_MODE=1` предназначен только для проверки на своём компьютере.
На сервере его не включайте и открывайте интерфейс через HTTPS.

## Настройка организации

Файл `config/company.json` задаёт начальное приветствие и меню бота. Путь к файлу можно
изменить переменной `QUEUE_GENERIC_CONFIG`. В Git этот файл не попадает.

При первом запуске профиль сохраняется в SQLite (`company_profile_json`). После этого
бот и админка используют сохранённый профиль; изменения категорий через админку
действуют сразу и сохраняются после перезапуска. Номера существующих пунктов стабильны,
отключённые пункты скрыты; номер 8 всегда занят активными заявками. При обновлении старые
настройки `request_menu_json` переносятся с сохранением названий и подсказок. Если в старой
админке сохранено больше восьми пунктов, перед запуском импортируйте профиль с 1–8
пунктами командой ниже; автоматическая миграция не отбрасывает лишние категории молча.

Для изменения приветствия, казахских текстов, номеров или обязательных полей через JSON
остановите Python-сервер, выполните с теми же переменными окружения и запустите его снова:

```bash
python scripts/import_company_profile.py config/company.json
```

Это явная замена текущего меню профилем из файла. Редактирование JSON без импорта не
перезаписывает настройки админки. Новые категории из админки получают русский текст
как запасной казахский; перевод можно задать при импорте профиля.

Самостоятельная регистрация сотрудников по умолчанию отключена. Администратор создаёт
аккаунты в разделе «Доступ». `QUEUE_ALLOW_SELF_REGISTRATION=1` явно открывает регистрацию
всем посетителям, которым доступен сайт.

```json
{
  "organization": "Название организации",
  "greeting_ru": "Добро пожаловать в службу поддержки",
  "greeting_kz": "Қолдау қызметіне қош келдіңіз",
  "categories": [
    {
      "number": 1,
      "key": "general",
      "label_ru": "Общее обращение",
      "label_kz": "Жалпы өтініш",
      "prompt_ru": "Опишите проблему и при необходимости приложите файл",
      "prompt_kz": "Мәселені сипаттап, қажет болса файл тіркеңіз",
      "required_fields": ["problem"]
    },
    {
      "number": 2,
      "key": "custom_printers",
      "label_ru": "Принтеры",
      "label_kz": "Принтерлер",
      "prompt_ru": "Укажите номер принтера и опишите проблему",
      "prompt_kz": "Принтер нөмірін көрсетіп, мәселені сипаттаңыз",
      "required_fields": ["reference", "problem"]
    }
  ]
}
```

Правила для категорий:

- от 1 до 8 категорий;
- `number` — номер пункта в меню: от 1 до 7 или 9. Номер 8 занят пунктом
  «Мои активные заявки», 0 открывает меню, 00 меняет язык;
- `key` — одно из `general`, `support`, `incident`, `database`, `mobile` или своё
  имя вида `custom_имя` (строчные латинские буквы, цифры и подчёркивание);
- `label_ru` и `label_kz` обязательны;
- `required_fields` — что бот обязательно спросит перед созданием заявки:
  `problem` (описание), `reference` (номер / идентификатор), `email`.

Перед первым обращением бот попросит пользователя указать подразделение и
должность и запомнит их.

## Переменные окружения

Полный пример — в файле `.env.example`. Сам сервер файл `.env` не читает:
на Linux подключите его через `EnvironmentFile` в unit-файле systemd.

| Переменная | Назначение |
|---|---|
| `WEBHOOK_TOKEN` | Общий секрет сервера и коннектора, обязательна, не короче 32 символов |
| `TICKET_APP_HOST`, `TICKET_APP_PORT` | Адрес и порт веб-сервера (по умолчанию `127.0.0.1:8000`) |
| `QUEUE_DATA_DIR` | Папка для базы данных и вложений |
| `QUEUE_WHATSAPP_AUTH_DIR` | Папка для сессии WhatsApp (вне каталога проекта) |
| `TICKET_API_URL` | Адрес сервера для коннектора (по умолчанию `http://127.0.0.1:8000`) |
| `QUEUE_TIMEZONE` или `QUEUE_UTC_OFFSET_HOURS` | Рабочий часовой пояс (по умолчанию UTC+5) |
| `QUEUE_ALLOW_SELF_REGISTRATION` | `0` по умолчанию; `1` разрешает открытую регистрацию сотрудников |
| `QUEUE_LOG_LEVEL` | Уровень журнала (`WARNING` по умолчанию, `INFO`, `DEBUG`); журнал пишется в stderr |
| `QUEUE_INSTRUCTION_SOURCE_URL` | Необязательно: Google Таблица с базой знаний, открытая по ссылке |

## Ограничения

- Коннектор работает через WhatsApp Web (библиотека whatsapp-web.js) и не
  является официальным WhatsApp Business Platform API. Перед коммерческим
  использованием оцените риски и соответствие правилам WhatsApp.
- Данные хранятся в SQLite. Система рассчитана на одну организацию и небольшую
  команду поддержки.

## Для разработчиков

Тесты (только стандартная библиотека, отдельная временная база):

```bash
python -m unittest discover -s tests -t .
npm test
npm run check:connector
```

Проверка `check:connector` загружает зависимости без запуска Chromium и подключения к WhatsApp.

На GitHub они запускаются автоматически на Ubuntu с Python 3.12 при каждом push
(`.github/workflows/tests.yml`). Они проверяют диалог бота в WhatsApp, создание и смену статуса заявок,
вход, раздачу статических файлов и проверку `config/company.json`.

Модули, вынесенные из `app.py`, получают общие сервисы через `bind(app_module)`
и обращаются к ним явно: `app.STORE`, `app.AUTH` и т. д. Маршруты POST описаны
таблицами `*_POST_ROUTES` в `queue_http_handler.py`; порядок таблиц в `do_POST`
задаёт этапы обработки (вход, авторизация, режим обслуживания, аудит форм).
Порядок CSS-файлов (`MAIN_STYLESHEETS` в `queue_ticket_views.py`) — это порядок
каскада: более поздний файл переопределяет более ранний.

Перед отправкой изменений в публичный репозиторий запустите проверку:

```bash
bash scripts/verify_snapshot.sh .
```

Скрипт ищет файлы с секретами и рабочими данными, проверяет синтаксис Python и JS.
Свои приватные маркеры (адреса серверов, имена компьютеров, названия организаций)
можно перечислить в `.private-markers`, по одному регулярному выражению на строку.
Этот файл не попадает в Git.

История изменений — в `CHANGELOG.md`, схема версий — в `docs/VERSIONING.md`.
