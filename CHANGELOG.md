# История универсальной версии

## Unreleased

- `app.js` (3500 строк) разделён на шесть файлов в `frontend/static/app/`: плеер, диалоги,
  просмотр медиа, чат, уведомления и основной скрипт. Браузеру сервер по-прежнему отдаёт их
  одним файлом `/static/app.js`, поэтому порядок загрузки не изменился. Самая большая часть,
  страница чата (2300 строк), осталась одной функцией

- `connector_receive.js` (2100 строк) разделён: вложения ушли в `connector_media.js`, звонки в
  `connector_calls.js`, поиск пропущенных входящих в `connector_recovery.js`. Код функций не
  менялся, к вызовам между частями добавлены только имена частей

- `queue_http_handler.py` (2400 строк) разнесён по темам: основа, сессии, чаты, заявки и
  админка лежат в `queue_http_base/sessions/chat/tickets/admin.py`, в самом файле остались
  таблицы маршрутов и порядок обработки. Код методов не менялся: байт-код всех 176 членов
  класса совпадает с прежним

- Исправлено: геолокация, пересланная копией, падала с ошибкой «нет текста». Теперь она
  уходит как геолокация. Сообщение с несколькими контактами копией не пересылается, и
  ошибка это прямо объясняет
- Исправлено: большое видео не успевало скачаться для пересылки копией. На загрузку теперь
  даётся 20 секунд и вторая попытка
- Поиск только что отправленного сообщения просматривает последние 600 сообщений, а не всю
  коллекцию WhatsApp Web
- `queue_whatsapp_handlers` без `bind()`: 112 обращений к `app.X` заменены набором
  `WhatsAppDependencies`. Это был последний модуль, читавший общий модуль приложения.
  Поведение не менялось
- Тесты: `tests/test_connector_api.py` — 24 сценария для адресов коннектора (синхронизация
  чатов, контактов, групп и сообщений, статусы, реакции, действия) и отправки вложений с
  сайта. Раньше эти адреса тестами почти не проверялись

- Исправлено: фото или файл, пересланные копией, могли не появиться в истории чата на сайте.
  Коннектор теперь сам сохраняет копию вместе с вложением сразу после отправки
- Исправлено: если сервер был недоступен сразу после пересылки копией, действие отмечалось
  ошибкой, хотя получатель уже получил сообщение, и повтор отправлял его второй раз

- Исправлено: отказ на POST-запрос без чтения его тела (регистрация выключена, чужое имя сайта,
  режим обслуживания) мог оборвать соединение, и браузер показывал ошибку вместо ответа.
  Сервер теперь дочитывает тело после любого POST

- Безопасность: `/health/connector` открыт без входа и отдавал QR-код привязки WhatsApp. Теперь
  QR-код возвращает только `/api/admin/connector-state`, доступный администратору
- Исправлено: автоответ мог сохраниться в отдельном чате `@lid`, из-за чего чат выглядел
  неотвеченным и «восстановление меню» присылало приветствие второй раз
- Исправлено: до выбора языка каждое сообщение пользователя получало приветствие заново.
  Повтор теперь ограничен, как у меню; цифра по-прежнему получает ответ сразу

- Исправлено: коннектор мог подтвердить отправку чужим сообщением из другого чата `@lid`, и
  тогда сайт показывал доставку не тому человеку. Теперь `@lid` сверяется с номером получателя,
  а если сверить нельзя, отправка остаётся в статусе «неопределённо»
- Исправлено: при пересылке копией голосовое уходило аудиофайлом, а стикер картинкой
- Исправлено: стили панели пересылки и баннера занятого чата блокировались политикой
  безопасности и не применялись. Теперь они лежат в `user-ui.css`
- Закрытие страницы во время ожидания новых событий больше не пишет трассировку в журнал

- Входящие одного чата доходят до сервера по порядку и после сбоя: повторная попытка больше не
  сдвигает сообщение в конец очереди, а новое сообщение ждёт застрявшие раньше него
- Очередь входящих удаляет сообщение только при ошибках 400, 413 и 422. При неверном токене и
  ограничении частоты оно остаётся на диске и будет отправлено повторно

- Коннектор разбит на части: отправка, приём, синхронизация, действия, жизненный цикл и
  общая основа. Поведение не менялось, команда запуска та же
- Исправлен сбой коннектора после того, как сервер восстанавливал локальное вложение:
  вызывалась несуществующая функция, из-за чего запрос завершался ошибкой
- Большая часть админки стала статической страницей: шаблоны лежат в `frontend/static/admin`,
  браузер заполняет их данными из `/api/admin-page` и сам экранирует значения. На сервере
  пока остаются только страницы входа, регистрации и смены временного пароля
- Новый API-ключ показывается один раз после перенаправления: секрет хранится в памяти сервера
  до пяти минут и не попадает в адрес страницы

- Код разложен по папкам: `backend/` (Python), `connector/` (WhatsApp) и `frontend/static/`
  (CSS и JS). Команды запуска не изменились: `python app.py` и `npm start` работают из
  корня проекта
- Большие блоки HTML вынесены из Python в `frontend/templates/` без новых зависимостей.
  Страницы совпадают с прежними побайтно, кроме токенов и времени
- Чат и группы стали статическими страницами в `frontend/pages/`: сервер больше не собирает
  для них HTML, а данные отдаёт через `/api/page-context` и `/api/groups-page`
- Список заявок и карточка заявки тоже стали статическими страницами. Данные приходят из
  `/api/dashboard-data` и `/api/ticket-page`, автообновление списка больше не получает HTML

- Исправлено: пересылка падала с ошибкой `reading 'forwardMessages'`, потому что нужный

- Удалены никем не вызываемые методы `TicketStore` (`allow_whatsapp_call`,

- Исправлено: страница «Контакты» и список групп отвечали 500, как только в них

- Перенесено из ветки fix/review-regressions-2026-11-04:
  - самостоятельная регистрация по умолчанию выключена (`QUEUE_ALLOW_SELF_REGISTRATION=1`

  - тесты на гонки двух диспетчеров и параллельный `request_id`, откат входящей

  - отложенная отправка: параллельный проход, проигравший гонку, не считается отправкой
  - резервные копии: пути в манифесте всегда с `/`, соединения SQLite закрываются

- Переходы диалога выделены в явные правила выбора действий; убраны мёртвые
  флаги, повторное сохранение дополнений и лишняя вложенность сбора черновика.
- SQL контекста, анализа сообщений и истории вынесен в `ContextRepository`.
  Публичные операции с черновиком и историей выполняются атомарно, включая
  перенос значения из истории сотрудником; схема базы сохранена.

  глобального словаря: независимый экземпляр не теряет пользовательскую категорию.

  доставки после сбоя хранилища.

- Логика входящих диалогов и доставки выделена в сервисы с явными зависимостями;

- Настройки меню больше не подменяют функции через `globals()` и не обновляют

- Удалены неиспользуемые разборщики меню и флаг свободного выбора категории.
- В браузере оставлен один адаптер `fetch`; контекст чата и уведомления об ошибках
  подключаются через подписки с отдельными копиями ответа. Обновлена версия ресурсов.
- Добавлены прямые тесты сервисов и браузерного адаптера, документация архитектуры.

- Меню бота: один источник настроек — база. Страница «Категории» редактирует
  приветствие и категории (номер, названия RU/KZ, подсказки, обязательные поля),

  Старый редактор `/admin/menu` (писал настройки, которые бот не читал) удалён
- Коннектор: добавлены отсутствовавшие модули `queue_delivery`, `queue_inbound_spool`,
  `queue_large_media`, `queue_avatars`; CI ставит зависимости с нуля и проверяет,

- Доступ: самостоятельно зарегистрированный аккаунт создаётся выключенным и не получает
  доступа к переписке и заявкам, пока администратор не включит его в «Пользователях»
- Бот: повторная доставка сообщения отсекается до любых изменений диалога (раньше
  повторная цифра меню стирала черновик заявки); проверка дубликата — в одном месте

- Отложенная отправка: постановка в очередь и смена статуса расписания выполняются
  одной транзакцией, а у каждой отправки есть постоянный идентификатор операции —
